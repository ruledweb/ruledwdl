1. Library Structure & Dependencies

This graph shows the file import structure. index.js acts as the public API surface, exposing internals. The layout layer depends on the pure render engine, which in turn orchestrates the parsers and builders.

2. Execution Sequence (composePage)

This sequence diagram maps the exact lifecycle when a host application requests a page to be composed. Notice the strict boundary between asynchronous data fetching (layout-composer/store) and the synchronous, pure generation of HTML (render-engine and below).

sequenceDiagram participant App as Host App participant LC as layout-composer participant Store as store.js participant RE as render-engine participant LP as layers-parser participant EB as element-builder participant DR as data-resolver participant MD as markdown.js App->>LC: composePage(store, project, page) activate LC LC->>Store: getLayout / getComponent / getComponentRegistry Store-->>LC: JSON Definitions LC->>LC: resolveBlocks & layout chain LC->>LC: collectAndDedupScripts LC->>LC: buildTokenStyles LC->>RE: renderAll(REG, COMPS, DAT) activate RE loop For each component RE->>LP: parseLayers(layers string) LP-->>RE: AST Node Tree RE->>EB: toHTML(node, attr, data, registry) activate EB EB->>DR: resolveAll(registry/attr) DR-->>EB: merged attributes EB->>MD: renderInlineMarkdown(text) MD-->>EB: safe HTML text EB-->>RE: Component HTML string deactivate EB end RE-->>LC: Inner Page HTML deactivate RE LC->>RE: wrapPage(html, title, scripts, seo, ...) activate RE RE-->>LC: Full string deactivate RE LC-->>App: { html, dynamic } deactivate LC
