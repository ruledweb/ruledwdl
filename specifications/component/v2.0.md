# WDL Specification: COMPONENTS (v2.0)

> **Specification Version**: `2.0`  
> **Status**: Active Standard  
> **Maintained in**: [`specifications/component/v2.0.md`](file:///home/pradeep/cloudflare/workers/wdl-core/specifications/component/v2.0.md)

---

## 1. Overview

The **`COMPONENTS v2.0`** specification expands WDL Layers expressions with multi-level repeater de-indentation (`<*N`), absolute depth referencing (`<@N`), automatic `wdl-comp="{semantic-id}"` attribute generation, clean **Flat String Arrays**, and programmatic **`WDLDomTree` 5-Element Tuple Arrays** (`[depth, operator, tag, semantic_id, repeator]`).

---

## 2. Schema Structure & Authoring Formats (v2.0)

`COMPONENTS` entries accept single WDL layer strings, flat string arrays, or programmatic 5-element tuple arrays (`WDLDomTree` state format):

### Format A: Flat String Array (Clean, Zero Indent Whitespace Burden)
```json
{
  "COMPONENTS": [
    {
      "$version": "2.0",
      "layers": [
        "form.login",
        "> div.container",
        "> h2.title",
        "+ input.email",
        "+ input.password",
        "+ button.submit",
        "<@1 a.forgot"
      ],
      "attr": {
        ".title": { "text": "${page_title}" }
      }
    }
  ]
}
```
*Note: Operators (`>`, `+`, `<`, `<@N`) explicitly define DOM depth. Authors do NOT need to add leading indent spaces in array strings.*

### Format B: 5-Element Tuple Array (`WDLDomTree` State Format)
```json
{
  "COMPONENTS": [
    {
      "$version": "2.0",
      "layers": [
        [0, "",    "form",   "login",     null],
        [1, ">",   "div",    "container", null],
        [2, ">",   "h2",     "title",     null],
        [2, "+",   "input",  "email",     null],
        [2, "+",   "input",  "password",  null],
        [2, "+",   "button", "submit",    null],
        [1, "<@1", "a",      "forgot",    null]
      ]
    }
  ]
}
```

---

## 3. 5-Element Tuple Specification (`[depth, operator, tag, semantic_id, repeator]`)

| Index | Field | Type | Description | Allowed Values |
| :--- | :--- | :--- | :--- | :--- |
| `0` | **`depth`** | `number` | Absolute DOM depth level ($0$ = root) | `0`, `1`, `2`, `3` |
| `1` | **`operator`** | `string` | WDL scoping operator | `""` (root), `">"`, `"+"`, `"<"`, `"<*N"`, `"<@N"` |
| `2` | **`tag`** | `string` | HTML element tag name | `"form"`, `"div"`, `"h2"`, `"button"`, `"input"` |
| `3` | **`semantic_id`** | `string` | Semantic class ID (strictly 1 ID) | `"login"`, `"container"`, `"title"`, `"email"` |
| `4` | **`repeator`** | `string \| null` *(optional)* | Multiplier or Data Loop key | `"3"` (`*3`), `"posts"` (`*posts`), `null` |

---

## 4. WDL Layers Grammar & Scoping Rules

Every element node in a `layers` expression MUST follow `tag.semantic_id`. Strictly **one** semantic class ID per node (`.class1.class2` is strictly restricted and throws parse errors).

| Syntax | Operator Name | Description |
| :--- | :--- | :--- |
| `>` | Child | Descend into child DOM level. |
| `+` | Sibling | Add sibling at current DOM level. |
| `<` | De-indent | Climb up 1 parent scope level (`<<` climbs 2 levels). |
| `<*N` | Repeater De-indent | De-indents $N$ parent levels (e.g. `<*3` $\equiv$ `<<<`). *(New in v2.0)* |
| `<@N` | Absolute Depth | De-indents directly to absolute depth level $N$ ($0$ = root scope). *(New in v2.0)* |
| `*N` | Static Multiplier | Renders element $N$ times (`li.item*3`). |
| `*items` | Data Loop | Renders array loop over `DATA.items` (`li.post*posts`). |

---

## 5. Automatic Attribute Emission v2.0

* **`wdl-comp="{semantic-id}"`**: Emitted on every element (class semantic ID or tag fallback, overrideable in `attr`).
* **`data-wdl-index="{index}"`**: Emitted automatically on data loop item elements.
